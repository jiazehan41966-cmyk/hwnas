# G1 NAS 暂停诊断分析

## 分析问题

当前 NAS 的 macro-F1 下降，究竟来自训练或来源追踪故障，还是冻结候选与搜索设计所形成的可复现精度—容量权衡？

## 证据最强的发现

下降在 14 个共同 fold-seed 单元上均可复现。NAS 的 macro-F1 均值为 `0.690453`，从零训练 MobileNetV2 为 `0.908091`，ImageNet 预训练 MobileNetV2 为 `0.930081`。NAS 相对两者分别低 `0.217638` 和 `0.239628`，没有赢得任何一个配对单元。

现有证据不像随机训练崩溃。所有已接纳运行均产生有限数值，预测与 checkpoint 已独立核验，并使用相同冻结归一化与数据划分协议。该候选的正式运行中期均值高于历史搜索阶段的 10 epoch、fold-0 代理值（`0.642115`），因此不存在“搜索代理承诺 MobileNet 水平、正式重训后突然失效”的证据。

## 机制诊断

当前最强解释是模型容量与搜索空间受限。NAS checkpoint 约含 `18,784` 个可训练参数，而 MobileNetV2 约含 `2,233,544` 个，约为前者的 `118.9` 倍。源搜索空间固定为四个浅层 stage block，主要变化来自算子选择；所选 route-clean 候选也只有四个可学习 stage block。按类别结果看，最大差距集中在预先声明的小样本或长尾类别 `fishing_net` 与 `small_propeller`，它们会显著拉低 macro-F1。

候选选择与已绑定的历史证据一致：搜索 summary 将 `rl_arch_135` 记录为 `best_candidate`，route manifest 又将相同 encoding 记录为 `claimable_board_best`。其 route 记录为 PASS，WNS 为 `0.094` ns，LUT 为 `18598`，DSP 为 `612`，BRAM 为 `127.5`，COM5 端到端 latency 为 `49.06201` ms。因此，它应被描述为“冻结的、route-feasible 的 Pareto 代表候选”，不能描述成预期在纯分类精度上击败 MobileNetV2 的模型。

## 有效性风险

源搜索仅使用 fold-0、10 个评估 epoch 和历史选择路径，不满足 group-safe 要求；同时，搜索空间上限与搜索策略彼此混杂。因此，本次运行可以度量该冻结候选的精度—资源权衡，但不能证明 RL、HW-PR-NAS、Random 或 Aging 哪一种策略本身更优。策略优劣仍必须通过已规划的等预算搜索实验判断。

## 决策含义

当前没有档案证据表明存在足以废弃 14 个已完成单元的代码或权重加载故障。完成唯一剩余单元可以闭合一个有效的负结果或精度—资源结果，但不等于接受该候选具备精度竞争力。扩大搜索空间、加入蒸馏或预训练、或者更换候选，都属于新实验，必须建立新的协议和 source freeze。下游 SURE 与 scratch-v2 仍分别受用户决策门禁约束。
