# 新版 MODNAS / 联合搜索 V2 对比协议（未冻结）

用户已确认采用正式 ZCU104 硬件约束口径，Ours 为联合搜索 V2。
本文件记录共同协议的接入状态，不构成已有搜索结果或可启动的训练冻结。

## 共同模型与算法

共同模型为完整固定 B1 骨干、四尺度 P2/P3/P4/P5、48 通道 neck、
直接 1×1 检测头，候选为 8 个 E0 与 64 个 E1。改变三个 TD 的 3/5 核，
以及整条 PAN 开关和启用时的三个 3/5 核；关闭 PAN 时不保留无效尾部选择。
每个数据集按实际类别数建立检测头，不能复用 Dataset A 的完整模型代价。

MODNAS 保留固定作者源的偏好条件化超网络、GDAS（可微采样）及 MGD
（多梯度下降）聚合，接入新架构编码与相同检测损失；最后候选独立重训。
ZCU104 成本应来自本轮实际新映射测量，原设备描述、Params 和旧网络总代价
不能替代硬件反馈。当前单步诊断不计为正式搜索。

Ours 保留独立候选训练、40/60/80 epoch（训练轮次）、量化精度与硬件代价的
Pareto 晋升、临界候选保留、弃选复核及三种子确认。因架构从 144 缩为 72，
阶段人数按原 1 / 0.75 / 0.5 比例适配为 72/54/36；这是显式工程适配，
不是旧运行的续跑。E0/E1 分别形成弃选复核的宏架构组。

联合 V2 的三种量化 profile（精度配置）与六种映射策略均保留，因此共同决策
空间需求为 72×3×6=1296 个架构/量化/映射组合。新版 MODNAS 当前仍只有
架构输出与 W8A8 单映射接口；其共同维度尚需接通。未接通前，不能将量化或
映射差异产生的收益归因于搜索策略。FPGA 资源未知或整数实现缺失的组合
保留其失败/未知状态，不加入有效 Pareto 集，不补填推算测量。

## 数据和选择

首个接通数据集为 Dataset A：冻结 train330、valid99，输入为单通道 640×640、
两类别。权重训练、BN 统计与 PTQ 校准只使用 train；搜索和候选选择使用 valid；
test 封存。真实数值诊断使用已保存的一步权重，不报告 mAP 或精度保持。

四数据集目标保持不变。当前 `configs/sonar_datasets_registry.yaml` 中 UATD
无 valid，Mine v2 尚无登记的 train/valid/test 分割；需在其正式搜索前建立
并冻结开发分割，不能从 test 选择候选。Classic SCTD 的项目分割有独立来源边界。
当前共同启动冻结只覆盖已核验的 Dataset A，不意味着其他数据集已就绪。

正式搜索种子为 42/43/44，双方分别完成三个独立搜索；V2 内部确认种子不代替
独立搜索重复。最终候选按相同独立重训、验证选择与测试协议比较。
工件采用 A/U/S/M + MOD/OUR + 资源档位 + seed，绑定架构哈希、权重、量化与
导出配置。下游部署沿用同一工件。

## 预算与计费

继承有来源的搜索阶段算子筛查：串行 HLS 计算延迟≤120000μs，
LUT≤161280、DSP≤1209、BRAM18≤436，器件 xczu7ev-ffvc1156-2-e、
Vitis HLS 2022.2、5ns。当前库的固定骨干已知部分和超预算，
正在开展有限映射改进实验；不自动放宽预算。
算子 HLS 资源峰值与串行求和仅是搜索层代理；整网布局布线、板上 25ms、
实测功耗和能量另按原登记核验。

共同搜索 GPU 型号、每个独立搜索的 GPU·h 上限、超时、资源档位、最终重训
轮次与候选数量尚未冻结；硬件门槛和新版后端验证完成后，以实际计时建立
可执行预算。不得仅以相同 epoch 数宣称总计算预算相同。MODNAS 超网、条件化
网络、预测器和筛选，V2 候选训练、PTQ 评价、晋升、复核及内部确认均计费。
共同 HLS 建库另报一次性 CPU/tool 时间与摊销，最终重训另列。

不同候选数、重复查询、缓存命中、失败/未知数分别记录。约束满足率的分母为
所有提出的不同候选；指标层级写明预测或 HLS，不称为板上可行率。
正式测试结果只在实际完成后产生；HV（超体积）仅在共同目标尺度与参考点
比较完整 Pareto 集时使用。
